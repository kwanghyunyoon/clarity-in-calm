# Expo HAS CHANGED

Read the exact versioned docs at https://docs.expo.dev/versions/v56.0.0/ before writing any code.

## Local Android builds crash from OOM — read before running Gradle

This machine has only 6.4GB RAM total, shared across every open repo/terminal. A local
`./gradlew assembleDebug` can get silently SIGKILLed by the kernel OOM killer mid-build —
no Gradle error, no exception, the daemon log (`~/.gradle/daemon/<ver>/daemon-<pid>.out.log`)
just stops mid-line during native C++ compilation (ninja/clang building an ABI variant).
This already happened once in the sibling `dreami` repo.

Cause: `org.gradle.jvmargs` reserves a large JVM heap for the Gradle daemon, and
`reactNativeArchitectures` in `android/gradle.properties` builds native modules for all 4
ABIs (armeabi-v7a, arm64-v8a, x86, x86_64) in parallel — each a separate clang/ninja process.
On a low-RAM box that combination exhausts memory.

Fix for local debug builds only (in `android/gradle.properties`):

```
org.gradle.jvmargs=-Xmx1536m -XX:MaxMetaspaceSize=512m
reactNativeArchitectures=arm64-v8a
```

Do **not** carry this into `app.config.js` / `expo-build-properties` — that's checked into
git and would also strip ABIs from release builds, which need all 4 for the Play Store.
`android/` is gitignored and regenerated by `expo prebuild --platform android --clean`, so
these two edits must be reapplied by hand after every clean prebuild, before building debug
APKs locally.
